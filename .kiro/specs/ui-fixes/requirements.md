# UI 修复需求文档

## 1. 功能概述

本规格文档涵盖两个 UI 修复需求：
1. 修复 Header 组件中智能体选择器下拉菜单被裁剪的问题
2. 适配 InputArea 组件的思考按钮以支持 OpenAI Response API 的多级别思考模式

## 2. 用户故事

### 2.1 智能体选择器下拉菜单修复

**作为** 用户  
**我想要** 在点击"新对话"按钮旁的智能体选择器时，能够看到完整的下拉菜单  
**以便** 我可以正常选择不同的智能体而不会被界面裁剪

**验收标准：**
1. 下拉菜单应完整显示，不被父容器裁剪
2. 下拉菜单应正确定位在按钮下方
3. 下拉菜单应有足够的 z-index 层级显示在其他元素之上
4. 在不同屏幕尺寸下都能正常显示
5. 暗色模式下也能正常显示

### 2.2 思考按钮多级别支持

**作为** 用户  
**我想要** 当选择使用 openai-response 协议的模型时，能够设置不同级别的思考强度  
**以便** 我可以根据需求控制模型的推理深度

**验收标准：**
1. 当模型使用 openai-response 协议时，思考按钮应显示为多级别选择器
2. 支持 5 个级别：无（none）、低（low）、中（medium）、高（high）、超高（very_high）
3. 当模型使用其他协议时，保持原有的开/关二元切换
4. 用户可以通过点击按钮循环切换级别，或通过下拉菜单选择
5. 当前选择的级别应清晰显示
6. 发送消息时应正确传递选择的思考级别
7. 在生成消息时应禁用级别切换

## 3. 技术约束

### 3.1 智能体选择器修复
- 必须保持现有的组件结构和 API
- 不能影响其他下拉菜单（模型选择器）的功能
- 必须兼容 Tauri 窗口拖拽区域（data-tauri-drag-region）
- 必须支持暗色模式

### 3.2 思考按钮适配
- 必须检测当前模型的 API 协议类型（chat_completions vs responses）
- 必须保持向后兼容，不影响现有的二元思考开关
- 必须更新 `onSend` 回调的参数类型以支持思考级别
- UI 组件应该紧凑，不占用过多空间

## 4. 非功能性需求

### 4.1 性能
- 下拉菜单的打开/关闭应流畅，无明显延迟
- 思考级别切换应即时响应

### 4.2 可访问性
- 所有交互元素应有适当的 aria 标签
- 键盘导航应正常工作（Tab、Enter、Escape）
- 颜色对比度应符合 WCAG 标准

### 4.3 可维护性
- 代码应遵循现有的项目结构和命名约定
- 应添加适当的注释说明修复原因
- 应保持组件的单一职责原则

## 5. 依赖关系

### 5.1 智能体选择器修复
- 依赖：`TauriAI-thinking-context/tauri-ai/src/components/Layout/Header.tsx`
- 可能需要调整父组件的样式或使用 Portal 渲染

### 5.2 思考按钮适配
- 依赖：`TauriAI-thinking-context/tauri-ai/src/components/Chat/InputArea.tsx`
- 依赖：`TauriAI-thinking-context/tauri-ai/src/types/index.ts`（可能需要添加新类型）
- 需要从 Provider/Model 配置中获取 API 协议类型

## 6. 测试要求

### 6.1 智能体选择器修复
- 手动测试：在不同屏幕尺寸下验证下拉菜单显示
- 手动测试：验证暗色模式下的显示效果
- 手动测试：验证多个智能体时的滚动功能

### 6.2 思考按钮适配
- 单元测试：验证不同协议类型下的按钮渲染
- 单元测试：验证级别切换逻辑
- 单元测试：验证发送消息时正确传递思考级别
- 手动测试：验证 UI 交互流畅性
- 手动测试：验证与后端的集成

## 7. 优先级

- **P0（高优先级）**：智能体选择器下拉菜单修复 - 影响基本可用性
- **P1（中优先级）**：思考按钮多级别支持 - 新功能增强

## 8. 里程碑

1. **阶段 1**：修复智能体选择器下拉菜单裁剪问题
2. **阶段 2**：实现思考按钮多级别支持
3. **阶段 3**：测试和验证
