# 手写体验优化需求（一）：低风险性能优化

## 1. 背景

当前练习系统的手写输入基于 Web Canvas + Pointer Events 实现，核心组件位于：

- `tauri-ai/apps/common/src/practice/ink/ScrollableInkPad.tsx`
- `tauri-ai/apps/common/src/practice/store.ts`
- `tauri-ai/apps/mobile/src/pages/PracticePage.tsx`
- `tauri-ai/apps/desktop/src/components/Practice/PracticeView.tsx`

在 OPPO Pad + OPPO 手写笔设备上，用户感知到明显的书写延迟。经代码审查，当前主要瓶颈位于前端 Canvas 渲染与合成路径，而不是后端调用。

本阶段目标是在 **不重构整体架构** 的前提下，优先通过低风险优化显著改善跟手性。

## 2. 目标

- 降低笔迹显示延迟，提升主观跟手性。
- 不改变当前数据模型（`InkState` / `InkStroke`）与练习数据存储结构。
- 不引入平台专有 SDK。
- 保持桌面端与移动端功能一致。
- 尽量避免影响现有全屏作答、撤销、清空、滚动、批改等功能。

## 3. 非目标

- 不在本阶段引入 Android 原生手写视图。
- 不在本阶段实现视口化渲染或 tile 渲染。
- 不在本阶段重做手写数据格式。
- 不以“接近系统笔记应用体验”为硬性目标，而是先完成明显可感知的性能改善。

## 4. 范围

### 4.1 包含范围

- Canvas 绘制热路径优化。
- Pointer 事件采样优化。
- DPR（devicePixelRatio）策略优化。
- 频繁布局读取优化。
- 绘图上下文状态切换优化。
- 性能埋点与对比验证。

### 4.2 不包含范围

- 长画布架构替换。
- 原生层桥接。
- 题目/批改业务逻辑修改。
- 手写内容导出格式升级。

## 5. 需求项

### 5.1 DPR 限制策略

系统应为手写 Canvas 引入单独的 DPR 上限，而不是直接使用完整 `window.devicePixelRatio`。

要求：

- 默认将手写 Canvas 的 DPR 限制在较保守范围内，例如 `1.5` 或 `2.0`。
- 允许后续扩展为“流畅优先 / 清晰优先”配置项。
- 该策略仅作用于手写画布，不影响整体 UI 渲染。

### 5.2 减少热路径中的布局读取

系统应避免在高频 `pointermove` 过程中反复调用 `getBoundingClientRect()` 或触发同步布局。

要求：

- 在 `pointerdown` 时缓存画布 rect。
- 在 viewport resize、滚动容器结构变化或 orientation change 时刷新缓存。
- `pointermove` 默认使用缓存 rect 计算坐标。

### 5.3 优化 Pointer 事件采样

系统应优先利用浏览器提供的 `getCoalescedEvents()` 能力，在可用设备上提升笔迹平滑度与采样效率。

要求：

- 若运行环境支持 `getCoalescedEvents()`，则一帧内处理合并事件样本。
- 若不支持，自动回退到当前单事件模式。
- 不得因该能力缺失导致功能不可用。

### 5.4 减少 Canvas 状态切换开销

系统应降低每条线段绘制时的 `ctx.save()` / `ctx.restore()` / 样式重复设置开销。

要求：

- 在一笔开始时预设稳定的上下文状态。
- 仅对必须随点变化的字段（如 pressure 对线宽的影响）做最小更新。
- 保证橡皮擦、荧光笔、钢笔、铅笔等笔刷效果不被破坏。

### 5.5 保持现有交互语义

优化后必须保持以下行为不变：

- 手指滚动仍可用。
- 手写笔书写不带动整页滚动。
- 全屏作答与普通作答的数据一致。
- 撤销、清空、提交批改不异常。

### 5.6 性能可观测性

系统应增加基础性能观测手段，支持后续判断优化收益。

要求：

- 可在开发模式下统计单次书写中的事件数、绘制耗时、合成耗时。
- 至少能区分“采样时间”“绘制时间”“提交时间”。
- 不得在生产模式下默认输出大量日志。

## 6. 验收标准

### 6.1 功能验收

- 用户可以连续书写、擦除、撤销、清空、滚动。
- 不出现笔迹错位、缩放异常、清空失败、手指/笔分流异常。
- 全屏与普通模式切换后，已写内容保持一致。

### 6.2 性能验收

在 OPPO Pad 真机上：

- 主观感受应明显优于当前版本。
- 连续书写时，笔迹跟手延迟应下降。
- 长时间书写 30 秒内，不应出现明显越来越卡的趋势。
- 不应出现明显新增的掉帧、白屏、黑屏或输入丢点。

### 6.3 回归验收

- 桌面端练习页功能正常。
- 移动端练习页功能正常。
- 手写数据仍可被原有存储结构读取。

## 7. 风险

- 低风险：逻辑局部、接口不变、兼容性较好。
- 中风险点：不同 WebView 对 `coalesced events` 支持不一致。
- 中风险点：DPR 下调后，部分用户可能感知到笔迹边缘略软。

## 8. 建议实施顺序

1. 加入 DPR 上限。
2. 缓存 rect，去除高频布局读取。
3. 接入 `getCoalescedEvents()`。
4. 优化 Canvas 状态设置与 segment 绘制热路径。
5. 加入性能埋点并在真机回归。
