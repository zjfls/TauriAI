📋 产品需求文档 (PRD)

版本: v0.1 | 状态: 评审中 | 更新: 2026-01-03

1. 项目背景

随着 AI 技术的发展，用户需要一个能够深度集成系统环境的智能助手。 现有的 AI 聊天工具（如 ChatGPT Web）无法访问本地文件、系统应用和上下文信息， 限制了 AI 在个人电脑场景下的实用性。

TauriAI 旨在打造一个类似 Raycast 的系统级 AI 助手， 能够感知并操作本地环境，成为用户的个人电脑智能中枢。

2. 项目目标

2.1 愿景

成为个人电脑上最强大的 AI 系统助手，连接用户与所有本地应用。

2.2 核心目标

  • 系统级集成：获取系统上下文，操作本地应用（Excel、日历、文件系统等）
  • 多模型支持：同时支持云端 API（OpenAI/Claude）和本地模型（Ollama）
  • 可扩展架构：支持 MCP 协议、Claude Skills 等主流扩展机制
  • 随时待命：常驻托盘，快速呼出

2.3 成功指标（MVP）

指标目标
基础聊天功能完成
托盘常驻完成
多模型切换支持 ≥2 种
响应延迟首字 < 2s

3. 用户画像

3.1 主要用户

用户类型特征核心需求
开发者 熟悉技术，追求效率 代码辅助、文档查询、自动化脚本
知识工作者 日常使用 Office、笔记软件 文档处理、日程管理、信息整理
创意工作者 使用设计/3D 软件（如虚幻引擎） 素材管理、工作流自动化

4. 使用场景

4.1 MVP 场景：AI 对话

场景：用户想快速询问 AI 问题

流程：

  1. 点击托盘图标或使用快捷键呼出聊天窗口
  2. 输入问题，选择 AI 模型（云端/本地）
  3. 获得 AI 回复，支持 Markdown 渲染
  4. 可继续多轮对话或关闭窗口

4.2 未来场景（规划）

  • 文件操作：「帮我整理下载文件夹，按类型分类」
  • 日历集成：「查看我明天的日程」
  • 应用控制：「打开 Excel 并创建一个销售报表模板」
  • 云盘同步：「把这个文件上传到我的云盘」

6. 非功能性需求

类别要求
性能 应用启动 < 3s，内存占用 < 200MB（空闲时）
兼容性 Windows 10+（MVP），后续支持 macOS、Linux
可用性 界面简洁，操作直观，无需学习成本
扩展性 架构支持后续添加新的 AI 模型和系统集成

7. 技术约束

  • 框架：Tauri v2 + React 19 + TypeScript + Rust
  • AI 接口：OpenAI API、Anthropic API、Ollama REST API
  • 扩展协议：MCP (Model Context Protocol)
  • 本地存储：SQLite 或 JSON 文件
