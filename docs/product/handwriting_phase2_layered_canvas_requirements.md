# 手写体验优化需求（二）：分层 Canvas 合成优化

## 1. 背景

当前手写组件采用“纸背景 + 离屏笔迹层 + 可见主画布整页合成”的方式。每次笔迹更新后，系统会在下一帧重新把背景和整张笔迹层合成到主画布上。

该方案在长页面和高分辨率设备上存在较高的每帧成本，尤其会放大 Android WebView 下的延迟问题。

本阶段目标是在 **不引入原生视图** 的前提下，优化渲染架构，使主画布不再承担整页重复合成成本。

## 2. 目标

- 降低每帧整页重绘与整页图层拷贝成本。
- 保持当前练习系统的数据结构和大部分 UI 交互不变。
- 为未来“视口化渲染”预留架构基础。

## 3. 非目标

- 不在本阶段实现仅视口绘制。
- 不在本阶段引入 Android 原生手写。
- 不重做存储格式。

## 4. 范围

### 4.1 包含范围

- 纸背景层与笔迹层分离。
- 取消每帧整页 `drawImage` 合成到单一主 Canvas 的方式。
- 清空、撤销、模板切换、重绘路径重构。

### 4.2 不包含范围

- tile 渲染。
- 虚拟滚动。
- 跨端原生桥接。

## 5. 需求项

### 5.1 分层渲染结构

系统应将手写区域拆分为至少两层：

- 背景层：仅负责纸张颜色与横线/网格模板。
- 笔迹层：仅负责用户笔迹。

要求：

- 背景层仅在尺寸变化、模板变化时重绘。
- 笔迹层仅在笔迹变化时更新。
- 不再要求每次书写都把整张笔迹图层重新绘制到背景画布。

### 5.2 重绘职责明确化

系统应明确以下操作的重绘范围：

- 新增笔画：仅影响笔迹层。
- 清空：仅清空笔迹层，并刷新状态。
- 撤销：按需重建笔迹层。
- 模板切换：仅刷新背景层。
- viewport 尺寸变化：按需重建相关层。

### 5.3 保持视觉一致性

分层后，系统必须保持与当前版本一致或更优的视觉表现：

- 纸张底色不变。
- 线条模板不变。
- 笔刷效果不变。
- 橡皮擦行为不变。

### 5.4 兼容现有交互

- 手指滚动逻辑保持可用。
- 全屏作答逻辑保持可用。
- 手写笔输入不应误触发页面滚动。
- 笔迹保存、恢复、批改摘要输入保持原行为。

## 6. 验收标准

### 6.1 功能验收

- 分层后所有原有交互均可正常工作。
- 清空、撤销、全屏切换、模板切换均无明显异常。
- 历史数据可正常显示。

### 6.2 性能验收

- 相比阶段一完成后的版本，长时间书写时帧稳定性进一步提升。
- 页面内容较长时，延迟增长趋势应明显减弱。
- 模板切换不出现明显闪烁或白屏。

## 7. 风险

- 中风险：Canvas 分层后，撤销与整页重建逻辑容易出现显示不同步。
- 中风险：橡皮擦如果依赖特殊合成模式，分层后需要重新验证视觉一致性。
- 中风险：全屏和普通模式复用同一组件时，尺寸同步逻辑可能出现边界问题。

## 8. 建议实施顺序

1. 抽离背景层绘制逻辑。
2. 将笔迹层作为独立可见层。
3. 去除整页合成路径。
4. 回归清空、撤销、模板切换、全屏切换。
5. 真机测试长页面书写表现。
