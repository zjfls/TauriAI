1. 设计理念

TauriAI 采用 "Code-System-Interface" (代码-系统-界面) 三层纵深防御体系。我们将错误视为一种结构化数据，而非简单的日志字符串。

2. 架构分层详解

第一层: 代码 (Rust Backend)

理念: "Fail Structured" (结构化失败)

第一层: 代码 - 错误注册表 (Error Registry)

解决痛点: "如何管理千奇百怪的业务错误？"

我们不再散落在各个文件中定义字符串，而是建立中心化的 枚举 (Enum) 仓库。

// src-tauri/src/errors.rs
pub enum AppErrorCode {
    ModelConfigMissing,  // 001: 还没配模型
    NetworkTimeout,      // 002: 网挂了
    OllamaServiceDown,   // 003: Ollama 没启动
    // 明天要加3个新错误？直接在这里加 enum variant 即可
}

impl AppErrorCode {
    // 统一管理错误文案和建议操作
    pub fn details(&self) -> (String, Vec<ErrorAction>) {
        match self {
            Self::ModelConfigMissing => (
                "未找到有效的模型配置".into(),
                vec![ErrorAction::navigate("去设置", "/settings")]
            ),
            // ...
        }
    }
}

第二层: 系统 - 富交互协议 (Rich Protocol)

解决痛点: "如何呈现链接和按钮？"

我们将单一的 suggestion 升级为 actions 数组，支持多种交互类型。

// 定义交互动作
struct ErrorAction {
    label: String,       // 按钮文字: "查看文档"
    action_type: String, // 动作类型: "link" | "navigate" | "retry" | "copy"
    payload: String      // 动作参数: "https://..." | "/settings"
}

// 最终传输的 JSON
{
  "code": "OLLAMA_DOWN",
  "message": "连接 Ollama 服务失败，请检查服务是否启动。",
  "actions": [
    { "label": "重试", "action_type": "retry", "payload": "" },
    { "label": "如何启动?", "action_type": "link", "payload": "https://ollama.ai" }
  ]
}

第三层: 界面 - 动态渲染器 (Dynamic Renderer)

实现能力: Markdown + 动态按钮组
  • 文案渲染：message 字段支持 Markdown 格式（如加粗关键信息）。
  • 操作区渲染：遍历 actions 数组，根据 action_type 渲染不同组件：
    • link → <a target="_blank"> (外部链接)
    • navigate → useNavigate() (内部跳转)
    • retry → Button (触发重试回调)
